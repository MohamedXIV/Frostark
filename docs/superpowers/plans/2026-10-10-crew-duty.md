# FrostArk #25 — Crew shifts, offshore dispatch, fatigue and repair jobs

**Date:** 2026-10-10. Base main `4386d9f2e45111abbf1c87dfdc6cc8cc70513633`. Issue #25 is Ready with #17/#24 CLOSED. Existing Unity PR #52 remains Draft/G2 not run.

## Design / source of truth
- Ship's unique authoritative `WorldState.CrewState` (different name from existing crew ID set) is immutable-on-commit, containing ordered crew members, their **primary** role (Engineering, Watch, Cooking, Medical, Repair), primary/backup skill permille, daily shift start+duration, fatigue, wounds, away status, and persistent ordered repair jobs.
- Existing `WorldState` crew IDs and crew station assignment commands remain a legacy compatibility contract for saves v1-v4. Authored `CrewState` cannot contain ID not in canonical WorldState crew registry. Assignments are not duplicated across two independent maps: the new crew skill/shift model is the authoritative *duty availability* while existing exclusive crew-station assignment remains an explicit command contract. Follow-up integration may migrate it to typed stations; record this boundary.
- Each world minute, assign one distinct eligible on-shift person per role, selecting strongest effective skill, ties broken by ordinal persistent ID, with no double-booking across roles. Backup skill allows a watchperson to cover Engineering if its engineer goes ashore. Off-duty, injured, exhausted and away modifiers are explicit; away=unavailable. A rested member improves; on-duty fatigues. Wounds persist until medical care future system, no magic autohealing.
- Repair queue is stored in CrewState, progressed only by effective repair-role staffing each world minute; job ID and remaining work units persist. If interrupted at 03:15, no repair work or fatigue accrues after that minute. No instant repair without available technician.
- `CrewMinuteSystem : IWorldMinuteSystem` runs in phase Crew from the same session-owned WorldState accessor/commit callbacks; thermal Heat-phase consumes its staffing efficiency through `ShipThermalModel.Step(..., efficiencyPermille)`, reducing boiler heat per fuel when qualified engineer dispatched ashore. Existing worlds with `CrewState.Empty` get **legacy 1000 permille** boiler efficiency until roster authored; no retroactive balance changes.
- Command `SetCrewAwayCommand` validates crew membership, staleness, duplicates and no-op state before committing once, with source events. No external roving manager.
- Binary save `FARKSAVE` v5 appends crew members, shifts, fatigue, wounds, away state and repair jobs to v4. Earlier v1–v4 load as `CrewState.Empty`, never fabricate roster progress. Strict validation of duplicate IDs/stray crew/unsupported flags and bound entries. Stable byte ordering and full fingerprint.
- No Unity/physical scene or real medical casualty simulation; G0/G1 proven separately from G2/G3/G4.
