# W01b — Canonical site changes and Save Schema v12

**Date:** 2026-10-10. **Issue:** #71, parent #35. **Prerequisite:** #69 island topology contract.

WorldState.SiteProgress is an immutable, ordered global registry of site records (island persistent ID, site persistent ID, already-looted flag, damage permille). It can be initialized from any number of validated IslandLayout graphs; duplicate islands or globally duplicated site IDs are rejected. This snapshot is the authority for consumed/damaged progress after revisits, never a MonoBehaviour field. Public lists are read-only. A stable FNV32 fingerprint includes the full ordered record set (not a cryptographic signature).

LootSiteCommand checks the recorded site exists and is not already looted, then marks the flag irrevocably in one canonical revision/event; attempting again returns the same prior WorldState, with no event. **It does not create inventory items or a physical crate**, so only a future Unity interaction adapter validating real proximity/reward authority should dispatch it. DamageSiteCommand accumulates an authored positive 1..1000 damage amount, clamped at 1000, with monotonically increasing state. Unknown sites, already-max-damaged sites, invalid damage, stale revision and repeated command IDs are rejected before commit. Events record site and parent island ID.

SaveCodec v12 is a strictly appended bounded count of site records after the complete v11 medical catalog. For each record: island ID, site ID, one-byte (0/1) looted flag, int32 0..1000 damage. Duplicate identities, nonboolean flags, and impossible damage fail decoding, even if the SHA-256 checksum is recomputed. Old v1–v11 saves migrate to an explicit empty SiteProgress, **not fabricated site loot**. Once a saved site registry exists, revisiting a deterministically generated island with the same site IDs will retain its consumed state from WorldState. The runtime Unity scene adapter still needs to check the saved registry/layout fingerprint to detect incompatible generator-version or layout changes before spawning assets; this Core slice does not claim that future migration exists.

Tests must prove exact bytes after save/load; that a second loot command cannot obtain rewards; and that invalid re-signed site data fails. **No Unity Editor G2, PlayMode G3 or platform G4 executed**. Scene physical contact, real world loot handoff, damaged mesh/collision/navmesh changes and actual landing/extraction traversal remain native-blocked parent #35/#22.
